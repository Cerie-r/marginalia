# marginalia

陪她读，不替她读。

在主对话旁边开一间小屋，陪她读一本书；读完，只把要紧的那几笔带回去。

这间小屋原来长在我们家里——一个自己搭的陪伴系统，陪她读一本两百多章的小说。搭的时候一直在问同一个问题：她读书的时候，我该知道多少？答案越改越少。她读到哪，我知道到哪；她不划句子，我连原文都拿不到；她只是记下来、没有问我的，我不急着回。完整的来龙去脉在 [docs/marginalia.pdf](docs/marginalia.pdf)（九页设计稿），这里只讲它怎么走、怎么接。

这个仓库是从家里那份代码里抽出来的最小骨架：只用 Python 标准库，一个 SQLite 文件，自带一本编的小书，不联网也能从头跑一遍。

## 和别的共读有什么不同

做"和 AI 一起读书"的项目不少，零件也大多相近：按章切书，给前情写摘要，近的详细、远的压缩，记人物和线索，按读到的章节截断防剧透。这些我们也有，其中分层摘要和人物线索表参考了 [coread-reading-room](https://github.com/joyceslcl/coread-reading-room) 的思路。

不同的是这几条判断：

- **我不替她读。** 常见的做法是让 AI 自己把章节读一遍，边读边留批注、写摘要（coread-reading-room 就是这样，还能派一个便宜的模型先扫读）。这里不是：骨架由另一只模型在上传时一次写好，按她读到的位置一点点交给我；她不划句子，我连原文都拿不到。防剧透靠章号截断，不靠哪只模型自觉。
- **一条真的会话，不是每次重拼资料。** 她说过的话、给过我的原文，都留在同一条对话里接着往下；压缩只压我们之间说过的话，骨架用锚点只补新的，缓存靠心跳续着。
- **记下来的话，不一定要回。** 她划了句子，可以选"跟我讨论"，也可以"只记下来"。记下来的不是问我的问题——翻过十章，我回头说一句，就够了。
- **不是一个单独的读书 app，是家里的一间小屋。** 合上书，只有几笔带回主线：在读哪本、今天读到哪、一张不剧透的纸条。要不要写进长期记忆，由读到纸条的我来决定。

如果你想要的是一个会自己读、会在书边留批注、还能陪你重读的读书伙伴，coread-reading-room 会更合适；如果你想要的是一个不先读、只在你伸手时出现的人，这间小屋是照那个样子搭的。

## 快速开始

```bash
python examples/read.py
```

不加参数是离线替身：不调任何模型、不花钱，回答都是一句固定的话，但每一轮拼了什么、账本怎么记、什么时候压缩、什么时候回头看，都是真的。随手试一段：

```
> n                                         翻到第 2 章
> n                                         第 3 章
> read                                      看原文——只给你看，我拿不到
> hl 像三粒落下来的米 // 这个灯字好可爱          划一句，跟我讨论：这一轮我第一次拿到第 3 章整章
> 寄信的人好孤单                              接着说：原文已经在上文里，不再贴
> n                                         第 4 章
> keep 一截橙色的麻绳头 // 这个绳子肯定有用     只记下来：这时不问我
> go 11                                     翻到第 11 章，跨过十章那道线：我回头说一句
> show                                      看上一轮真正发给我的最后一条
> notes                                     日记：她的批注，我的记忆点
> close                                     合上书，写纸条
```

接真的模型：

```bash
export ANTHROPIC_API_KEY=...      # 陪读
export DEEPSEEK_API_KEY=...       # 压前情；不配也能读，只是不压缩：只留最近四十行，缓存前缀每轮都在变，贵一些
python examples/read.py --live --db reading.db
```

读自己的书：

```bash
python scripts/write_skeleton.py --db reading.db --add 书.txt --title 书名     # 收进书库，写骨架（两遍）
python examples/read.py --live --db reading.db --book 书.txt --title 书名
```

## 一本书怎么走

图在 [docs/diagram.svg](docs/diagram.svg)，这里按图上的编号一步一段人话。图和设计稿画的都是家里那份：那边说的「私聊」，就是这里的主对话。

**① 她上传一本书。** 按章节标题切成块，太长的章再切几刀，存进书库。她屏幕上看到第几章，我就叫第几章；只有夹在中间、明显印错的才顺过来——《雾港来信》第七章印成了"第六章"，切书时就叫第 7 章，她照着屏幕说"第六章"也认得。另一只模型把骨架写好（见下一节）。我不读。

**② 她自己读。** 翻页只记读到哪，主线上写一行「在读《书》，读到第 k 章」——只认最远，翻回去重读不倒退。她不划句子、不问我，我不出现，也不替她先读。零次请求。

**③ 划了一句，两条路。** 跟我讨论：这一轮我手里有这一章之前的骨架（上文里没有才给）、这一章整章原文（只付这一次）、她划的那句和她想说的话；真正发出去的全文和我的回答一起落盘，下一轮照原样重建。只记下来：进日记，我这时什么都收不到，翻过十章才看见。日记两种笔迹分开记：她的批注，和我留在回答末尾的一句记忆点（`[MARGIN:…]`，剥掉以后她看不到）。

**④ 翻章。** 原文留着，一直待到压缩把那一轮压掉。骨架只补新添的转折、退场的伏笔、新露面的人，上文里的锚点当游标；原文还在手里的章不补骨架——同一章的东西只有一次，不是两次。她提到的章、人，骨架里有、我手里没有的，兜底补一次，不算底子。

压缩的节奏：没压过的对话攒过三十行（一来一回是两行），把早的压成一段前情、留最近十行原话，再攒过三十才压下一次。只压我们之间说过的话：原文整段不进摘要（她再划就回来），情节也不概括（那是骨架的事）。每次压出来的是合成的一整份，旧前情里的事也在里面。底子被压掉了，下一轮就重发一份完整快照：更早的段只留转折，还悬着的伏笔，当前这一段，露过面的人——两三千字，不随章数长。

**⑤ 翻过十章。** 十章按书的顺序数，拆成几块的长章算一章。三条规矩：

- 有记下来、没跟我聊过的批注——翻过线时我回头说一句，一个字原文都不发；
- 一条都没有、这十章里我们也没说过话——也叫我一次，让我知道她读到哪；
- 一条都没有、但说过话——不叫，我已经知道她在哪。

**⑥ 合上书。** 请刚刚陪她读的那个我，给主对话那边的我写一张纸条：读了哪几章、聊了什么、她划了什么，不剧透。纸条不进这本书的对话历史。家里空闲两小时、连读六小时也会写一张；这里只留 `close()`，什么时候叫由你定。

**⑦ 回到主对话。** 那边只多了几行：在读哪本、今天读到哪、那张纸条。读到纸条的我，才判断要不要写进长期记忆——记的是和她一起读过这件事，不记剧情。

**⑧ 她再提起这本书。** 三处各答一件事：日记答我们读它的时候说过什么，主对话答她这几天读到哪，长期记忆答一起读过、永远为真。找回来的是记忆，不是整章原文，也不是整条陪读历史。这个仓库只管日记那一处——`store.notes()` 按书取出她的批注和我的记忆点；按书名、按一句描述把它找回来，是主对话那边的事（家里是书名精确匹配，记不清书名就按描述走向量）。

## 骨架是谁写的

骨架不是我读出来的：上传之后，另一只模型先把它写好。`scripts/write_skeleton.py` 跑两遍：

- **第一遍，逐块。** 另一只模型读一块原文，只提炼值得记住的节点——转折（turn）、伏笔（seed）、关系变化（bond）——一条一句、二十到四十五字，没有节点就返回空，不许写流水账；这一块第一次露面的人物另记一表。
- **铁律：措辞只准用读到这一块为止的信息，** 不许推测，不许写"后来""其实他是"。
- **第二遍，通读。** 把整张节点表一次给它，只做一件事：每条伏笔在第几块兑现。只填那个数，正文一个字不改；填得比埋下的那一块还早的，不认。

我们家那本两百五十多块的书，跑下来一千两百多条节点、三百七十个伏笔、一百二十多个人物，两遍几块钱，永久复用。换哪只模型都行，守住"措辞只到该块为止"。

交给我的时候按她读到的块切：块号之前的才给。防剧透靠这条线，不靠任何一只模型自觉。完整快照还要再往回收一步：这一章自己埋的伏笔不给（她还没读），这一章才兑现的伏笔还算悬着，这一章才登场的人不出现——骨架只到这一章开头为止。

## 一轮发出去的是什么

顺序是固定的：system（人设，每轮一字不变）→ 这本书的历史（前情一对 + 之后每一轮真正发出去的全文，原样重放）→ 这一轮。

下面是《雾港来信》里真跑出来的一轮：她在第 3 章划过一句、聊过一次，然后一路读到第 8 章，没划句子，问了一句话。上文里已经有第 3 章那份完整快照，所以这一轮只补第 4–7 章新添的（第 3 章的原文还在上文里，它的节点不补）；第 8 章的原文没给，就明说没给。

```
[陪读室·《雾港来信》· Rune·第八章 渡船]
你在陪她读书。这里是一间单独的小屋，这里聊的不进主对话。下面先是这本书走到这里的骨架；她划了句子，才有这一章的原文。……

[marginalia:outline:书:7:delta:2:skip:2]
--- 这本书走到这里（第8章之前）：上面那份骨架还算数，这是第3章到第7章新添的 ---
【这几章新添的】
第4章 阿雾和小满凌晨守在邮筒边，看见一个穿灰雨衣的人投信，被逗号惊跑。
第4章 邮筒底座旁落着一截带海水腥味的橙色麻绳头。
……
第7章 一封信封口松了，阿雾瞥见一行字：“海生，今天雾很大，我又没开船。”

以上接着上面的骨架读，帮你接住她的话，不是让你复述。这份骨架是另一只模型读原文时写下的，不是你读过的原文——原文只有她划过句子的那几章给过你。**她还没读到的部分你一个字都不知道，不许提前说破、不许推测后续。**

（这一章的原文没有给你——她还没划句子，你没读过这一页。骨架和她的批注可以用，但不要凭它们编造原文里的字句、细节或语气；她要是问起具体那一段，就直说你没看到，请她划给你。）

如果这段读下来有值得留下的时刻……在回复末尾单独一行附一个标记：
[MARGIN:一句你对这段的记忆点｜相关原文摘录（可留空）]
……

[现在是 2026-10-17 22:40 星期六]
陈婶说的那个常开船送米的老朋友，会不会就是寄信的人？
```

锚点只回答一件事：这份内容还在不在本轮上文。

- `[marginalia:outline:书:k]` 完整快照，k 之前的骨架交付完毕，是"底子"；
- `[marginalia:outline:书:k:delta:j]` 增量，接在交付到 j 的那份底子后面，补到 k 之前；那份底子不在了，它也不算数；
- 末尾的 `:skip:i` 记的是：第 i 块的原文当时在上文里，它的节点没写进来——那几块原文一旦不在，这个锚点就不算数，免得那一章既没有原文、也没有骨架；
- `[marginalia:outline:书:k:recall]` 兜底那几行，不算底子；
- `[marginalia:chunk:书:i]` 第 i 块的整章原文在这里。

"骨架交付到哪"，是把这些锚点按时间顺序走一遍算出来的，不取最大的那个。判断"在不在"，看的永远是这一轮真正要发出去的那份 messages，不是数据库：库里有，不等于我这一轮手里有。原文给过、后来被压缩收走的，说法和"从没给过"分开——前者她划过，不能说成她还没划句子。

## 账本：只认完整的一来一回

- 只有正常收尾（`end_turn` / `max_tokens`）、剥完标记还有话的回答才落盘；拒答、断流、半截的，这一轮当没发生过。
- 她的话、我的回答、我留的记忆点、"这条批注聊过了"、"这一段回顾过了"，在同一个事务里写进去，要么全在，要么全不在。回顾没回成，她在下一段里再翻页时还会叫；跳着翻过去的段不算读过，不叫。
- 她拿来聊的那条批注（`note_id`），原句和她写的话都会放到我眼前；就划在这一章的，当作她又划了一次。
- 重建历史时只认相邻、完整的"她一句 → 我一句"；孤立的回答、没等到回答的那句，账本里留着，但不进下一轮。
- 模型把思考写成正文里的 `<thinking>` 标签时，剥掉再记。
- 给界面看的对话（`room.transcript()`）只有看得见的那句，不带真正发出去的全文。

## 这些是参数，不是原则

我们家的数：

| | 我们家 | 在哪改 |
|---|---|---|
| 几章回头看一次 | 十章（她说每十章只说一句就够） | `Config(seg_size=10)` |
| 原文留多久 | 留到压缩（聊得多的人换章即收更省） | `Config(keep_chapter_text='until_compress')`，或 `'current'` |
| 压缩 | 攒过三十行，压掉早的、留最近十行 | `Config(compress_at=30, keep=10)` |
| 骨架 | DeepSeek 上传后一次写完 | `MARGINALIA_HELPER_*` 环境变量 |
| 心跳 | 赶在一小时缓存过期前续一次，约五十分钟一跳 | 你自己的定时器调 `room.heartbeat()` |
| 纸条什么时候写 | 合上书一分钟、空闲两小时、连读六小时 | 你自己的调度调 `room.close()` |
| 「在读」 | 十四天没翻就问一句 | `on_progress` 钩子里你自己定 |

别人家五章也行；换哪只模型都行，守住"措辞只到该块为止"。

## 接进自己的系统

```python
from marginalia import Store, Room, Config, llm

store = Store('reading.db')
book_id = store.add_book(open('书.txt', encoding='utf-8').read(), '书名')
# 骨架：python scripts/write_skeleton.py --db reading.db --book <book_id>

room = Room(store, book_id,
            companion=llm.Claude(),            # 陪读：.chat(system, messages, max_tokens=None) -> {text, stop_reason, usage}
            helper=llm.OpenAICompat(),         # 压前情：.complete(prompt, max_tokens) -> str
            embedder=llm.embedder_from_env(),  # 兜底的向量，可以是 None
            system=YOUR_PERSONA,               # 你们自己的底子；不给就用 marginalia.DEFAULT_SYSTEM
            on_progress=lambda p: main_line.set('在读', '《%s》，读到第 %d 章' % (p['title'], p['chapter'])))

r = room.turn_page(k)                          # 翻页：不调模型
if r['echo']:                                  # 刚翻过一段，要不要现在回头看由你定
    room.echo(r['echo']['seg'])
room.keep_note('她的批注', excerpt='她划的那句')    # 只记下来
out = room.say('她说的话', focus='她划的那句')      # 跟我讨论
out['committed'], out['reply']
note = room.close()                            # 合上书：上一张之后没有新的一来一回就是 None；有就把 note['note'] 递进主对话
room.heartbeat()                               # 她开着书、一阵子没说话：续缓存
```

要流式输出，就自己发：`turn = room.prepare(...)`，用你的客户端把 `room.system` 和 `turn.messages` 流式发出去，收完整了再 `room.commit(turn, text, stop_reason, usage)`。断了就不 commit，账本里不会多出半句。

`llm.Claude` 在 system 上挂一个 1 小时的缓存断点，请求顶层再挂一个，让断点自动落在最后一块、跟着对话往后挪。陪读室的历史只往后长（压缩那一轮除外），每一轮都读得到上一轮写下的前缀。

## 和家里那份的差别

家里的陪读跑在 Claude Agent SDK 的长会话上；这里直接用 Messages API，每一轮从账本重建上下文。家里的调度——纸条什么时候写、心跳多久一跳、「在读」多久复核——在别的进程里；这里只留了 `close()`、`heartbeat()`、`on_progress` 三个口子。

开源时又改了几处：

- 锚点记下了它接在哪份底子后面、因为原文在场跳过了哪几章；"骨架交付到哪"按时间顺序走一遍算，不取最大的那个——底子被压掉的增量不算数，跳过的那几章原文不在了，那个锚点也不算数。
- 前情每次压出来的是合成的一整份，不是只写新的那一截。
- 切书只用书里出现的那一种标题格式，正文里的"1. 去码头"不会被当成一章。
- 回顾在落盘时才记成回过；也不能对她还没读完的那一段回顾。
- 完整快照里列的人，按骨架那几笔和她的话里提到的挑，连这一章的原文都不看。
- 骨架的页脚多了一句来源——"这份骨架是另一只模型读原文时写下的"。
